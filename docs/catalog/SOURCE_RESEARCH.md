# Source research for the internet application catalog

Observed on 2026-11-13, UTC. This is the T12 research artifact, not an enabled advisor or installation catalog. Coverage is 47/47 registry rows. The merged ChatGPT / Codex row contains at least two products, so the minimum product count after separation is 48; CLI variants are additional identities, not extra coverage credit.

## What was actually checked

Read-only HTTPS requests retrieved public vendor release metadata/pages, official vendor GitHub releases, Homebrew cask metadata and Apple public store listings. Requests used a 10 second timeout, at most three workers and serialized each host within each probe batch. No app, updater, installer, package script, host inventory or account session was executed. No schedule, daemon or telemetry was added. The evidence file contains 146 observations: 138 successful HTTP responses and 8 bounded errors. Of these, 38 are static Homebrew source reads, not extra vendor-version probes. The checked responses and exact per-request `observed_at`, status, final URL and selected evidence are in [SOURCE_RESEARCH_EVIDENCE.json](SOURCE_RESEARCH_EVIDENCE.json). HTTP Date is transport metadata, not publication time. Some page excerpts are deliberately shortened and are not full archived documents. A bounded error means unavailable for this observation, never proof that a source does not exist.

Applied procedure: official OpenAI documentation was retrieved for the OpenAI product distinction. Other facts use each vendor, Apple's service and the manager's own repository/API. Existing local config supplied research leads only. Existing routing names, comments, version-history claims and bundle identities were not treated as independent public verification.

`reviewed/high` means confidence in the explicitly described public metadata or listed identity. It does not certify stable eligibility where the row says unknown, newest compatibility, executable identity, native updater ownership, install safety or first-install success. `reviewed metadata` has narrower scope; `unknown/conflicting` and `incomparable` block an automatic recommendation. No numeric confidence score is used.

## Decision rule and limits

Keep three independent observations: `global_latest_stable`, `latest_compatible_stable` and `actually_offered`. Public metadata here can sometimes establish the first. No local environment or signed binary was inspected, so the second is generally unknown, except published compatibility constraints. No account/GUI check occurred, so `actually_offered` is unknown for all 47 rows. Apple values are `listed`, never `offered`. Storefronts are US unless explicitly labeled PL; storefront listing does not establish account eligibility, region availability, phased release, iPad-on-Mac availability or an older compatible download.

A GitHub latest release is eligible only after checking `prerelease=false`, `draft=false` and product/edition. Explicit Stable category/channel is stronger evidence than the bare words latest, currentRelease or main. A version without an rc suffix is not itself proof of stable. Firefox Developer Edition and DeepSeek nightly/RC do not become stable because they are the newest builds. Product-specific release/build normalization is required: do not compare a commit hash, Darwin version, Electron version, package hash or mobile edition number to a desktop marketing version.

Installation source and updater are separate fields. Homebrew's `auto_updates=true` is a manager declaration that the app has its own updater, not evidence that every installed copy may safely use it. A compatible native updater can coexist with a cask-delivered vendor bundle when identity, artifact ownership, manager policy and the approved update scope match. MAS receipts and MDM/enterprise management remain source constraints. Nothing here authorizes adoption, uninstall, receipt replacement, source migration, launch, helper installation or downgrade. When equally current compatible stable releases are proven, preserve the current source. A newer source is only a proposal with `migration_required` if switching sources is needed. Unknown/partial/incomparable sources cannot lose a speed ranking.

Compatibility shorthand below is Homebrew `depends_on.macos` at observation time, prefixed B; it is not verified vendor minimum OS or a claim that an older Mac receives that version. `B unknown` includes an empty constraint. Artifact URL can name arm64/universal, but actual architecture and signature were not inspected. Runtime probes must validate minOS/architecture from reviewed metadata or signed artifacts. Licensing/access terms were not reviewed for any row: `license_review=unknown` applies to every row, including free downloads, open-source upstreams and store listings. No row is first-install verified, and no unknown Team ID was fabricated. A reviewed first-install recipe still needs exact license/terms, bundle/Team ID, complete artifact effects, arm64/minOS, stable channel and a disposable-Mac acceptance result.

## Useful comparisons now

Cursor's explicit stable metadata currently has a newer release label than the cask. Chrome's stable version catalog also has a newer label, but a catalog entry is weaker evidence of actual rollout availability. ## Historical speed claim: evidence still missing

There is no historical winner. A single snapshot cannot answer which channel is usually fastest. The planned local, opt-in observation history must cover at least five matched stable releases over at least 30 days, separately for product, edition, architecture, OS compatibility and storefront. Record vendor `published_at`, manager commit/publication time when available, store release timestamp, and local `first_observed_at` independently. Do not backfill first observation from a feed pubDate. Poll gaps create intervals, not exact lag values. A missed check, 429, offline response or staged rollout remains a censored/unknown observation. No background schedule or telemetry is proposed or enabled.

A defensible result should report sample size, covered dates, matched release identifiers and artifact mapping, timestamp basis, uncertainty intervals, median/range of observed delays, and exclusions. If matching dates or offered state are unavailable, say only that a channel currently lists a newer stable. Do not rank native above Homebrew above MAS, and do not promise future speed.

## Runtime advisor implementation, 2026-11-13

The selected-product advisor is now implemented separately from the observations above. `config/channel_sources.json` preserves all 47 research rows and identifies 48 GUI products after splitting ChatGPT and Codex. The manifest grants public metadata checks only. Its entries grant no installation, replacement, launch, license or updater-ownership authority. Unknown identity and stable policies remain explicit.

`channel_probes.compare_selected_channels` accepts selected product IDs or matches current inventory through reviewed exact bundle IDs and verified installed cask receipt identities. Names and local SUFeedURL values do not establish a match. Unknown installed products stay unmatched. The coverage command can show those limitations without fetching the whole catalog.

Checks use the shared HTTPS policy with exact source hosts, at most three simultaneous requests and one request per host, ten seconds per source, and a sixty second invocation budget. Successful metadata is cached for 24 hours in private local state with its original observation time. Explicit refresh skips the normal cache but respects Retry-After. No schedule, account session, app launch, package execution or telemetry is involved.

The recommendation keeps global stable, compatible stable, actually offered and the specific recommended release separate. A public App Store result remains listed, even for a verified Mac product. Unknown architecture or minimum OS prevents a compatible recommendation. A staged release can remain the latest compatible observation while an older listed release is the available recommendation. Equal releases preserve the current source. Conflicting source ownership blocks a recommendation. Native updater preference needs an explicit reviewed ownership binding and a matching eligible release observation.

Local history records publication time separately from first observation and its probe interval. Cached reads never become new first observations. At least five matched stable releases over thirty days are required before history is qualified for analysis. This implementation makes no historical speed claim. It does not infer an installable product, an offered update or a universal winner from the preserved research rows.

The guarded fixture suite covers source-ahead and tie cases, MAS ahead and later, prerelease and edition exclusions, incompatible and staged releases, unknown region/compatibility, reviewed identity matching, cache expiry, Retry-After, concurrency and the invocation budget. No live application update or fresh installation was performed by these checks.
